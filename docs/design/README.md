# Design docs

A design doc works through a choice that isn't settled yet. It compares the
options against the [requirements](../architecture/quality-attributes.md),
says what's still unknown, and ends in one or more
[decision records](../adrs/README.md). Once it's decided, it stops changing.

Files are named `YYYY-MM-DD-short-title.md` after the date the doc was
started.
